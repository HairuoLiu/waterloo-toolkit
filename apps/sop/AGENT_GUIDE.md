## 1. 这个 SOP 是什么

- **定位**：面向滑铁卢大学新生（以研究生 MEng / Co-op 为主）的入学全流程指南，是本工具箱**最重要的一个子 App**（主站首页置顶整行 banner 指向它）。
- **不是**一次性文章，而是**持续长大的 Wiki**：使用者在不同时间段遇到新问题，就往「踩坑记录」追加一条。
- **线上地址**：<https://hairuoliu.github.io/waterloo-toolkit/apps/sop/>
- **页面形态**：左侧目录 + 全文搜索，右侧正文（大厂文档站形态）。

## 3. 三种最常见的修改

### 3.1 ⭐ 追加一条踩坑记录（最高频，只改 `data.js`）

打开 `apps/sop/data.js`，往 `window.SOP_LOG` 数组里**追加一个对象**即可，页面会自动渲染，**不用碰 HTML**：

```js
window.SOP_LOG = [
  // ↓ 复制下面这段改成你的内容 ↓
  {
    date: "2026-09-10",
    tag: "银行",
    title: "TD 开户被要求补充住址证明",
    body: "只带护照+学签不够，窗口要求额外住址证明（租房合同或含地址的水电账单）。\n建议落地先办手机卡，用账单当住址证明。"
  }
];
```

**字段规范**：

| 字段 | 必填 | 说明 |
|---|---|---|
| `date` | ✅ | `YYYY-MM-DD`。也可用阶段标签如 `"行前 / 抵达"`，但**推荐用日期**，便于按时间理解 |
| `tag` | 可选 | 分类短标签。建议复用已有：签证 / 银行 / 手机 / 住宿 / 医保 / 选课 / Co-op / 税务 / 交通 / 建站 |
| `title` | ✅ | 一句话说清「什么事」，≤20 字为佳 |
| `body` | ✅ | 详情。**换行用 `\n`**（页面会渲染成 `<br>`），不要写 HTML 标签 |

**写法要求**：
- 新条目加在数组**末尾**（页面按数组顺序渲染，末条=最新）。
- 条目之间用英文逗号分隔，最后一条**不要**加尾逗号（保持与现有风格一致）。
- 字符串里出现英文双引号要转义，或改用单引号。
- `body` 里**不要**写 `<div>`、`<b>` 等 HTML——会被当纯文本显示出来。

### 3.2 ⭐⭐ 给某个阶段加一条清单项（改 `index.html`）

找到对应 `<section>` 里的 `<ul class="check-list">`，照抄一行 `<li>`：

```html
<li>激活 <b>WatIAM 账号</b> 与 UW 邮箱（@uwaterloo.ca），这是所有学校系统的入口。</li>
```

约定：
- 一行 = **一个可执行动作**，动词开头（激活 / 申请 / 办理 / 确认 / 预订…）。
- 关键名词用 `<b>` 加粗（如系统名、金额、截止日），**不要**整句加粗。
- 需要外部链接用 `<a href="…" target="_blank" rel="noopener">`，**外链必须带 `rel="noopener"`**。

### 3.3 ⭐⭐⭐ 新增一个章节 / 阶段（复制模板）

把这段插到 `#log` 章节**之前**（踩坑记录应永远在最后），然后改 `id`、`data-toc`、`h2` 与内容：

```html
<section id="coop" data-toc="阶段五 · Co-op 求职">
  <h2>⑦ 阶段五 · Co-op 求职（时间线）</h2>
  <ul class="check-list">
    <li>……</li>
  </ul>
  <div class="box-warn"><b>关键提醒：</b> ……</div>
</section>
```

⚠️ **两个必须，漏了会出 bug**：
1. **`id` 必须唯一**，且不与现有 `top / overview / pre / arrive / enroll / life / log` 重复。
2. **必须带 `data-toc="…"`** 属性。左侧目录是 JS 扫描 `.sop-main section[data-toc]` 自动生成的，**没有这个属性，新章节不会出现在目录里，也搜不到**。

⚠️ **编号坑**：`h2` 里的 ①②③④⑤⑥ 是**手写死**的（非自动编号）。
若把新章节插在中间，请手动把后续 `h2` 的序号顺延，否则会出现两个 ⑤。
（目录左侧的序号是 JS 自动生成的，无需手动维护。）

## 4. 可复用的样式积木（class 速查）

这些 class 已在本页内联 `<style>` 中定义好，**直接复用，不要自己新造 CSS**：

| class | 用途 | 用法 |
|---|---|---|
| `.check-list` + `<li>` | 可打勾清单（自动带 ☐） | `<ul class="check-list"><li>…</li></ul>` |
| `.phase` + `.num` | 四阶段概览卡片 | 见 `#overview` 内现成写法 |
| `.box-good` | 绿色 = 建议 / 最佳实践 | `<div class="box-good"><b>优先级建议：</b>…</div>` |
| `.box-callout` | 蓝色 = 说明 / 补充信息 | 同上 |
| `.box-warn` | 金色 = 警告 / 关键提醒 | 同上 |
| `.pill-row` + `.pill` | 标签胶囊行 | 用于 hero 区 |
| `.two` | 两列栅格（≤760px 自动单列） | 包住两个 `.phase` |

颜色/圆角/阴影统一取自 `assets/style.css` 的 CSS 变量：`--brand`（UW 金 `#FED34C`）、`--brand-deep`、`--line`、`--card`、`--muted`。**要加新组件请沿用这些变量，不要写死色值。**

## 5. 页面是怎么工作的（理解后再改，不容易改坏）

`app.js` 是一个 IIFE，按顺序做 5 件事：

1. **渲染踩坑记录**：读 `window.SOP_LOG` → 生成 `.log-item` 塞进 `#sop-log`。
2. **生成左侧目录**：扫描 `.sop-main section[data-toc]` → 生成 `<a href="#id">`。
3. **全文搜索**：输入关键字（防抖 140ms）→
   - 每个 section **先从原始 HTML 还原再重新高亮**（所以可反复搜索、可无损清空）；
   - 命中处包 `<mark>`（金色高亮）；
   - 未命中的章节隐藏，目录项变灰并显示命中数徽标；
   - 踩坑记录里未命中的**单条**也会隐藏。
   - 支持 `/` 或 `Ctrl/⌘+K` 聚焦搜索框，`Esc` 清空。
4. **滚动联动**：滚动时高亮目录里当前所在章节（阈值 120px）。
5. **分享**：`navigator.share` 优先，否则复制链接 + toast。

> **给维护者的实现提醒**：搜索的高亮是「整段 innerHTML 重建」实现的，因此
> **不要给 section 内部的节点挂事件监听器**（每次搜索都会被销毁重建）。
> 需要交互的元素请放在 section 之外，或在 `app.js` 里用事件委托重新绑定。

## 6. 硬约束（红线，违反会出问题）

1. 🔴 **本仓库是 PUBLIC**：**禁止**写入任何个人隐私或敏感信息——签证/移民状态、护照号、SIN、银行账号、家庭住址、财务细节等。
   写 SOP 内容时同样适用：只写**通用流程与公开信息**。
2. **只用相对路径**：站内链接写 `../../assets/style.css`、`../locker-finder/`；
   **禁止**以 `/` 开头的绝对路径（GitHub Pages 跑在子路径下会 404）。
3. **不要 `fetch` 本地 JSON**：数据一律内嵌为 `window.XXX = [...]` 的 `.js` 文件。
4. **不要动 `assets/style.css`** 来改 SOP：那是全站共享样式，改了会影响其它 4 个子 App。
   SOP 专属样式写在 `index.html` 的内联 `<style>` 里。
5. **`data.js` 必须在 `app.js` 之前**引入，否则 `window.SOP_LOG` 为空、记录区显示空白。
6. **顶栏结构不可改**：左侧 `brand`（回首页），右侧 `.top-actions` 含 **GitHub 图标链接 + 分享按钮**。
   样式只能用 `assets/style.css` 现成 class，禁止自创顶栏 CSS。
7. **封面**：`cover.svg` 只能由 `assets/gen_cover.py` 生成，**禁止手写 SVG 或换成 PNG/JPG**。
8. **别用 `git rebase`**（历史上曾三次损坏 `.git`）。分叉时用 `git pull --no-rebase`。

## 8. 常见错误 & 排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 新章节不在左侧目录里 | `<section>` 缺 `data-toc` 属性 | 补上 `data-toc="章节名"` |
| 踩坑记录区空白 | `data.js` 在 `app.js` 之后引入，或 `SOP_LOG` 语法错误（多了/少了逗号） | 调整 script 顺序；用 `node -c data.js` 检查语法 |
| 搜索后内容不还原 | 搜索清空逻辑依赖 `_sopOrig`；若手动改过 section 的 innerHTML 而未刷新会异常 | 刷新页面即可；不要在控制台里手工改 DOM 后搜索 |
| 改了 `assets/style.css` 后其它页面也变了 | 那是全站共享文件 | 改回原样，SOP 专属样式放 `index.html` 内联 `<style>` |
| 页面 404 / 样式丢失 | 用了 `/` 开头的绝对路径 | 改回相对路径 |
| `h2` 出现两个 ⑤ | 序号是手写的 | 手动顺延后续编号 |
| 提交后线上没变 | GitHub Pages 传播延迟 | 等 1–2 分钟再 curl |

## 9. 怎样算「完整的 SOP」（完整性标准）

判断一篇 SOP 是否合格，每个阶段应覆盖以下 7 个维度。缺项就是可以补的内容：

| 维度 | 要回答的问题 |
|---|---|
| **目标** | 这一阶段结束时要达成什么？ |
| **时间窗口** | 什么时候做？（如「开学前 1–3 个月」「落地 3 天内」） |
| **前置条件** | 开始前必须先有什么？（如拿到 LOA 才能申学签） |
| **步骤清单** | 具体动作，一条一个动作，可逐项打勾 |
| **所需材料** | 要带/交哪些文件？（护照、学签、住址证明…） |
| **常见坑** | 别人容易栽在哪？（→ 沉淀到「踩坑记录」） |
| **官方链接** | 权威依据在哪？（uwaterloo.ca / IRCC / Service Canada…） |

**当前覆盖状态**：四个阶段的「步骤清单」已齐备；
「时间窗口」「所需材料」「常见坑」「官方链接」仍有大量补全空间 —— **这是最值得投入的补完方向**。

**补充原则**：
- 优先写**只有真正经历过才知道**的细节（如「当场核对 Study Permit 姓名拼写」）。
- 不确定就标注「待核实」，**不要编造**金额、截止日或政策；一律以官方页面为准。
- 涉及年份/金额的信息，尽量注明「截至 YYYY 年」，避免过期误导。
