# 周中临时住宿 · 使用说明与资料

> 一句话用法：**按呼叫顺序从上往下打电话** —— 先让对方报价，再用页面里的英文脚本还价；目标价与话术都写在每家的详情里。

---

## 一、核心概要

给**住在多伦多及周边、每周赴滑铁卢 2–3 晚**的人找「相对长期的临时住宿」。

- **给谁**：家在多伦多 / 密西沙加等地，但每周要在滑铁卢校区待 2–3 晚的研究生（通勤 + 住宿比整租便宜，比每天开车往返省时间）。
- **解决什么**：普通酒店按日计价极贵，而长住月租又要求整月；本工具筛出**愿意做周中长住、可谈价**的 50 家候选，并把谈价信息摊开。
- **怎么用一句话**：按城市 / 等级筛选 → 按 `rank` 从上往下打 → 用页面里的英文脚本谈价 → 谈成后把结果记下来。

**窗口假设**：2026-09-08 ~ 2026-12-08，共 **27 间夜**（页面内所有「总价 / 月均」都基于这个假设；改窗口需重算）。

---

## 二、怎么用

| 功能 | 用法 |
|------|------|
| **Top 50 候选** | 覆盖 Waterloo / Kitchener / Cambridge / Guelph 四城 |
| **城市筛选** | 顶部按城市过滤（离校区近 vs 便宜） |
| **等级筛选（tier）** | A / B / C 三档，`score` 越高越靠前 |
| **搜索** | `matches` 对名称、地址、城市、类型做模糊匹配 |
| **点行看详情** | 地址、电话、邮箱、官网、`pub`（公开价）/ `neg`（谈判目标）/ `tgt`（理想价）、月均、评分与备注 |
| **谈价策略** | 页面正文给出「先让对方报价 → 报出你的 27 间夜总量 → 用周边低价压价」的套路 |
| **英文电话谈判脚本** | 可直接照读的英文话术（含开场、报价、还价、要书面确认） |
| **Call #1 → #8 呼叫顺序** | 排好优先级的拨打顺序，避免同时打 50 家 |

## 三、怎么设计

**文件清单**

| 文件 | 职责 |
|------|------|
| `index.html` | 正文（筛选条、候选表格、谈价策略、英文脚本、呼叫顺序）+ 顶栏 + 详情弹层 |
| `app.js` | 筛选、搜索、表格渲染、详情弹层、评分 / 等级样式映射 |
| `data.js` | `window.ACCOM`：50 条候选数据（**自动生成，勿手改**） |
| `cover.svg` | 封面（`assets/gen_cover.py` 生成） |

**数据结构**（`data.js`）
```js
window.ACCOM = [
  {
    "name": "Kitchener Motel",
    "city": "Kitchener",
    "type": "汽车旅馆",
    "bf": "N",                      // 是否含早餐 Y/N
    "addr": "1485 Victoria St N",
    "phone": "+1 519-745-1177 / 1-800-574-2156",
    "email": null,
    "web": "kitchenermotel.ca",
    "url": "http://www.kitchenermotel.ca",
    "pub": "$59–75/晚（周/冬特价另议）",   // 公开价
    "neg": "$50/晚",                    // 谈判目标价
    "tgt": "$48/晚",                    // 理想价
    "cost27": "$1,350",                 // 27 间夜总价
    "mo": "$450",                       // 月均（展示用）
    "monthly": 450,                     // 月均（数值，用于排序/筛选）
    "ls": "高（周价/小厨房套房/21翻新房）", // 谈价空间 Leverage
    "score": 89.0,                      // 综合评分
    "tier": "A",                        // 等级 A/B/C
    "rating": "6.6/10",
    "rating_note": "Booking·83条 · 便宜老旧、隔音差，位置便利",
    "rank": 1                           // ★ 呼叫顺序
  }
];
```

**关键函数**（`app.js`）：`matches`（模糊搜索）、`render`（表格）、`openDetail` / `closeDetail`（详情弹层）、`ratingClass` / `tierClass`（配色）、`esc`（转义防 XSS）。

**依赖**：无第三方库、无 CDN；样式来自 `../../assets/style.css`。

## 四、怎么改

| 想改什么 | 动哪里 | 改完怎么验证 |
|---|---|---|
| 更新某家的价格 / 电话 | `data.js` 对应条目 | 表格与详情弹层同步更新 |
| 加一家候选 | `data.js` 追加对象，**务必填 `rank` 与 `tier`** | 出现在表格里；按 rank 排序位置正确 |
| 改变住宿窗口（不再是 27 间夜） | 重算 `cost27` / `mo` / `monthly`，并改正文里的窗口说明 | 页面总价与正文一致 |
| 改筛选维度 | `app.js` 的 `matches` 与筛选条 | 各筛选组合下条数正确 |
| 改谈价脚本 | `index.html` 正文段落 | 通读一遍英文，确保可直接照读 |

> 改了行为 / 数据 / 结构 ⇒ **同一次提交必须更新本文件**（见根 `README.md` 的 R2）。

## 五、事实红线

- 电话、地址、邮箱、官网、价格**一律照抄来源，绝不编造**；拿不到的字段写 `null`，不要瞎填。
- `pub` 公开价与 `neg` / `tgt` 是**两回事**：前者是来源数据，后者是**推断的目标价**，页面必须区分展示。
- 评分（`rating` / `rating_note`）是第三方平台快照，须带**样本数与检索日期**。
- 价格随季节波动，所有报价**以电话确认结果为准**。
